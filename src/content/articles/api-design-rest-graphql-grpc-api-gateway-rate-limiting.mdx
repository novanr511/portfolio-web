APIs are the contracts between systems. Design them like products.

**Direct answer:** API design defines how systems communicate. REST (resource-oriented, HTTP semantics), GraphQL (query flexibility, single endpoint), gRPC (high-performance, contract-first). API gateways provide routing, auth, rate limiting, observability. Versioning, pagination, error handling, and documentation determine developer experience and platform longevity.

## RESTful design

**Resources:** nouns, not verbs. `/users`, `/users/{id}/orders`.

**HTTP methods:** GET (read), POST (create), PUT/PATCH (update), DELETE (delete).

**Status codes:** 200/201/204 (success), 400 (client error), 401/403 (auth), 404 (not found), 409 (conflict), 422 (validation), 429 (rate limit), 5xx (server).

**Idempotency:** GET, PUT, DELETE idempotent. POST not. Idempotency keys for POST.

**Versioning:** URL (`/v1/`), header (`Accept: application/vnd.api.v1+json`), query param. Prefer URL for visibility.

**Pagination:** cursor-based (opaque cursor) > offset/limit. `first`, `after`, `hasNextPage`.

**Filtering/sorting:** `?filter[status]=active&sort=-created_at`.

**HATEOAS:** links in responses for discoverability.

## GraphQL

**Schema-first:** SDL defines types, queries, mutations, subscriptions.

**Queries:** client specifies exact fields. No over/under-fetching.

**Mutations:** explicit input types, return payload with errors.

**Subscriptions:** WebSocket, server-pushed updates.

**N+1 problem:** DataLoader pattern (batching + caching).

**Complexity:** query depth/cost analysis, query cost limits, persisted queries.

**Federation:** schema stitching across services (Apollo Federation, GraphQL Mesh).

## gRPC

**Protocol:** HTTP/2, Protocol Buffers (protobuf). Binary, efficient, streaming.

**Service definition:** `.proto` defines services, messages, RPC methods (unary, server-streaming, client-streaming, bidirectional).

**Code generation:** `protoc` generates client/server stubs (Go, Java, Python, Node, etc.).

**Interceptors:** auth, logging, metrics, retries, timeouts.

**gRPC-Web / gRPC-Gateway:** browser support, REST/JSON transcoding.

## API Gateway

**Functions:** routing, auth (JWT, API key, mTLS), rate limiting, quotas, caching, transformation, logging, observability.

**Patterns:**
- **Backend for Frontend (BFF):** per-client API.
- **Aggregator:** compose multiple services.
- **Edge:** external traffic ingress.

**Products:** Kong, Kong Gateway, Kong Konnect, Apigee, AWS API Gateway, Azure API Management, Kong Konnect, Traefik, Envoy, KrakenD, Tyk, Gloo.

## Rate limiting & quotas

**Algorithms:** token bucket (burst), leaky bucket (smooth), sliding window (accurate), fixed window (simple).

**Dimensions:** per IP, per API key, per user, per tenant, per endpoint.

**Response:** 429 + `Retry-After`, `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`.

**Distributed:** Redis-backed (token bucket, sliding window log), consistent hashing.

## Error handling & observability

**Error format:** RFC 7807 (Problem Details for HTTP APIs). `type`, `title`, `status`, `detail`, `instance`.

**Logging:** structured (JSON), correlation IDs, request/response sampling.

**Tracing:** OpenTelemetry, W3C Trace Context, distributed tracing.

**Metrics:** RED (Rate, Errors, Duration), USE (Utilization, Saturation, Errors).
