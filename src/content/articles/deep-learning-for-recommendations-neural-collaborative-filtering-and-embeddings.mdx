Matrix factorisation was the dominant recommender approach for years: represent users and items as vectors, and score a pair with a dot product. Its simplicity is its strength and its ceiling. Deep learning for recommender systems begins with the question of what happens when you replace that fixed dot product with a learned function.

**Direct answer:** Neural collaborative filtering replaces the fixed inner product with a neural network that learns how user and item embeddings should interact, which can capture structure a dot product cannot. The gain comes with costs — more parameters, more data, less interpretability, and harder serving. It helps when there is enough interaction data to learn the structure and when the ranking problem is complex; on sparse data, a well-tuned simpler model usually wins. The same trade-off appears in modern ranking models: DeepFM was built to learn "both low- and high-order feature interactions" end to end, which is a more powerful objective and a larger data requirement.

## What the dot product cannot express

In matrix factorisation, a user's score for an item is the dot product of their two vectors. That is a multiplicative interaction with a fixed form, and it imposes a geometry on the problem: similarity means proximity in a shared latent space.

A learned interaction function removes that constraint. The network can discover that different dimensions matter differently for different users, that interactions are non-linear, or that the user's vector and the item's vector should be combined in a more complex way. This is a genuine increase in expressive power.

Wang et al. supply the more important argument in their work on Neural Graph Collaborative Filtering: existing approaches — "ranging from early matrix factorization to recently emerged deep learning based methods" — typically obtain a user's embedding "by mapping from pre-existing features that describe the user (or the item), such as ID and attributes". The consequence is that "the collaborative signal, which is latent in user-item interactions, is not encoded in the embedding process", and the embedding "may not be sufficient to capture the collaborative filtering effect". Their answer is to integrate the interaction graph into the embedding itself.

That is the real distinction between the deep and the classical line: not that the network is bigger, but that structure which used to appear only in the loss can be made part of the representation.

## Embeddings are the interface

A deep recommender still needs representations of users and items, and those representations can come from several places:

**ID embeddings** are learned from the interactions themselves. They work well for frequently seen entities and badly for rare ones, which is the cold-start problem in another form.

**Content embeddings** come from attributes, text, or images. Sentence-BERT derives "semantically meaningful sentence embeddings that can be compared using cosine-similarity", which is the basis for representing an item by its description. Word2vec embeddings do the same for shorter text. These help new items participate before they have interactions.

**Graph embeddings** incorporate the structure of the interaction network, as in NGCF. This is where a deep model can encode information that is present in the data but absent from any single row.

A practical system usually combines them. The choice matters because each source brings its own failure mode: ID embeddings need data, content embeddings inherit model bias, and graph embeddings need the right edge definition.

## Ranking is where most of the value is

Recommenders produce candidates; rankers order them, and the ranking objective is where most commercial value sits. DeepFM's approach is to model low- and high-order feature interactions end to end, and their evaluation covers "both benchmark data and commercial data" — the right instinct for a field where offline gains often fail to transfer.

The transfer problem is worth stating plainly: a ranking model optimises the metric it was trained on, usually click-through rate, which is not the business objective. A more expressive model can be better at optimising the wrong thing. The system therefore needs a second measure — retention, repeat purchase, total value — that the model was not trained against, and an experiment that tests whether the offline gain appears online.

## The costs that come with the gain

**Data.** A more expressive model needs more examples to fit without overfitting. On a small catalogue or a young product, a simple collaborative model with regularisation will often beat a deep one.

**Serving.** Embeddings and neural layers add latency to an operation that runs on every page view. The infrastructure cost is real and has to be measured alongside the quality gain.

**Interpretability.** A dot product can be inspected; a multi-layer interaction network cannot be understood in the same way. For a system whose decisions affect what people see, that matters for debugging and for governance.

**Stability.** Deep models are more sensitive to their training setup, and their behaviour on a shifted distribution is harder to predict. A catalogue change that would slightly move a matrix factorisation model can produce a qualitatively different ranking from a deep one.

## When to use which

Use a deep recommender when you have substantial interaction data, a complex ranking problem with many feature interactions, and infrastructure that can serve embeddings at the required latency. Use a simpler model when data is sparse, the catalogue is small, or the main problem is cold start rather than ranking quality.

The honest way to decide is a controlled comparison on your own data, with the evaluation design that recommender experiments require — position logging, an appropriate randomisation unit, and a horizon long enough to include the feedback loop.
