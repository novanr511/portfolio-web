Security is not a product. It is a process.

**Direct answer:** Cybersecurity protects confidentiality, integrity, and availability (CIA triad) of systems and data. Core practices: threat modeling (identify risks), Zero Trust (never trust, always verify), incident response (detect, contain, recover), and continuous monitoring. Security is a shared responsibility across engineering, operations, and leadership.

## Threat modeling

**STRIDE:** Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege.

**PASTA:** Process for Attack Simulation and Threat Analysis (7 stages).

**Attack trees:** root goal → sub-goals → attack vectors.

**Data flow diagrams:** trust boundaries, entry points, data stores, external entities.

**MITRE ATT&CK:** adversary tactics, techniques, procedures (TTPs). Map detections to techniques.

## Zero Trust architecture

**Principles:** never trust, always verify; least privilege; assume breach; verify explicitly.

**Components:**
- **Identity:** strong auth (MFA, passwordless), conditional access, identity providers (Okta, Entra ID, Ping).
- **Device:** compliance (MDM/EDR), health attestation, certificate-based auth.
- **Network:** micro-segmentation, software-defined perimeter, no implicit trust zones.
- **Application:** least privilege access, just-in-time (JIT) access, API security.
- **Data:** classification, encryption (at rest/in transit), DLP, rights management.

**Implementation:** start with identity + device, expand to network + data. Continuous verification, not one-time.

## Incident response lifecycle (NIST SP 800-61)

1. **Preparation:** IR plan, runbooks, playbooks, tools (SIEM, EDR, SOAR), training, tabletop exercises.
2. **Detection & Analysis:** alert triage, enrichment, scoping, severity classification (SEV-1 to SEV-4).
3. **Containment:** short-term (isolate), long-term (eradicate). Short-term: network isolation, account disable. Long-term: malware removal, patching.
4. **Eradication:** remove artifacts, close vulnerabilities, rotate credentials.
5. **Recovery:** restore from clean backups, verify integrity, monitor for re-infection.
6. **Post-incident:** root cause analysis (5 Whys), lessons learned, update playbooks, update defenses.

## Security program pillars

- **Governance:** policies, standards, risk appetite, board reporting.
- **Vulnerability management:** scanning (SAST, DAST, SCA, container, container), prioritization (EPSS, KEV), SLAs, patch management.
- **Identity & access:** least privilege, PAM, JIT, certification campaigns.
- **Data protection:** classification, encryption, DLP, key management (HSM, KMS).
- **Security awareness:** phishing simulations, training, culture.
- **Third-party risk:** vendor assessment, contractual security clauses, continuous monitoring.

## Detection & response stack

- **SIEM:** log aggregation, correlation, alerting (Splunk, Sentinel, Datadog, Elastic).
- **EDR/XDR:** endpoint detection, behavioral analytics (CrowdStrike, SentinelOne, Defender).
- **NDR:** network traffic analysis (ExtraHop, Corelight, Zeek).
- **SOAR:** automation, playbooks (Splunk SOAR, Cortex XSOAR, Tines).
- **Threat intel:** feeds (MITRE, AlienVault, MISP), TIP integration.
