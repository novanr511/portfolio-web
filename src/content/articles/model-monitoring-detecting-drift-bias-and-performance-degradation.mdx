A model deployed is a model decaying.

**Direct answer:** Model monitoring tracks whether a deployed ML system continues to perform as expected. It detects data drift (input distribution shift), concept drift (relationship between features and target changes), prediction drift (output distribution shift), bias/fairness violations, and infrastructure issues. Without monitoring, silent failures erode business value silently.

## Types of drift

**Data drift (covariate shift):** input feature distribution P(X) changes. Example: user demographics shift, sensor calibration drifts, new product categories appear. Detected via statistical tests (KS test, PSI, chi-square) on feature distributions.

**Concept drift (prior probability shift):** P(Y|X) changes. The relationship between features and target evolves. Example: fraud patterns change, user preferences shift, economic conditions alter purchasing behavior. Detected via performance decay on labeled data or proxy metrics.

**Label drift (prior probability shift):** P(Y) changes. Class distribution shifts. Example: fraud rate drops from 1% to 0.1%.

**Prediction drift:** output distribution P(Ŷ) changes. Often an early warning signal. Monitor prediction histograms, mean prediction, class proportions.

## Detection methods

**Statistical tests:**
- **PSI (Population Stability Index):** bins feature values, compares bin proportions between reference and current. PSI > 0.25 = significant drift.
- **KS test / KS statistic:** compares cumulative distributions.
- **Chi-square / Jensen-Shannon divergence:** for categorical features.
- **Wasserstein distance / Earth Mover's Distance:** for continuous distributions.

**ML-based detectors:** train a classifier to distinguish reference vs current data; AUC > 0.55 indicates drift.

**Performance monitoring:** track ground-truth metrics (accuracy, F1, AUC) when labels available. For delayed labels, use proxy metrics (prediction confidence, feature drift as proxy).

## Bias and fairness monitoring

Track disparate impact across protected attributes (gender, race, age):

- **Demographic parity:** equal positive rate across groups.
- **Equal opportunity:** equal true positive rate.
- **Equalized odds:** equal TPR and FPR.
- **Calibration:** predicted probabilities match observed frequencies per group.

Monitor these metrics per slice; alert on threshold breaches.

## Infrastructure and operational monitoring

- **Latency:** p50, p95, p99 inference latency.
- **Error rates:** 5xx, timeouts, OOM, model exceptions.
- **Throughput:** requests per second, queue depth.
- **Resource utilization:** GPU/CPU memory, CPU utilization.

## Monitoring architecture

- **Logging:** structured logs for every prediction (features, prediction, latency, metadata).
- **Aggregation:** periodic (hourly/daily) aggregation of drift metrics, performance metrics.
- **Alerting:** threshold-based (PSI > 0.25, accuracy drop > 5%), anomaly detection on metric time series.
- **Dashboards:** per-model, per-slice, per-environment.
- **Retraining triggers:** automated or manual based on drift severity and performance decay.

## When to retrain

- **Scheduled:** weekly/monthly for high-velocity domains.
- **Triggered:** drift threshold breached, performance below threshold.
- **Continuous:** online learning (rare, complex).
